# 故障排除

如果您遇到问题，请检查[我们的 GitHub 问题跟踪器](https://github.com/renode/renode/issues)之前是否未报告过该问题。请注意，我们也有内部问题跟踪系统，我们可能已经知道您的问题，但只是没有来得及解决它。尽管如此，还是值得提请我们注意您的用例，以便我们知道它正在影响您/您的用例。

Renode 团队和社区也可能知道一些解决方法或其他方法来实现您想要做的事情，并提出这些建议。

为了加快获取帮助的过程，请：

1. 将您的示例简化为仍然不适合您的最小示例（例如，将崩溃的软件简化为表现出相同症状的最基本等效项，仅执行不适合您的 Monitor 命令等）。
2. 说明您正在使用的作系统、使用的 Renode 版本，如果可能，请说明您要实现的目标（上下文）
3. 提供 1：1 重现问题所需的所有文件和命令（`.repl`、`.resc` 文件），ELF 格式的预编译二进制文件
4. 提供日志 - Renode 日志和 UART 终端输出（如果相关）
5. 如果您可以为示例提供源代码以及编译说明，这将有所帮助

遵循这些建议将有助于我们确认错误并采取行动。

Please note that if for some reason you are not able to share your setup publicly, or you need priority support, Antmicro provides commercial services for Renode.
For more information, please contact <support@renode.io>.
请注意，如果由于某种原因您无法公开分享您的设置，或者您需要优先支持，Antmicro 将为 Renode 提供商业服务。有关更多信息，请联系 <support@renode.io>.
