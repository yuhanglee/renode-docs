# 时间框架

## 时间和性能单位

仿真中的时间称为 _虚拟时间_ （与 _主机时间_ 或 _实时_ 相反），以 _虚拟秒_ 表示。目前， _虚拟时间_ 的分辨率，即最小可表达的时间量化，是 10^-6  _虚拟秒_ 或 1 _虚拟微秒_ 。CPU 的性能以  _MIPS_ 单位（ _每秒数百万条指令_ ）表示，是一个整数值。这意味着设置最小时间量允许性能为 1 _MIPS_ 的 CPU 只执行一条指令。

:::{note}
对于性能高于 1  _MIPS_  的 CPU，可以使用特殊的 _步进_ 模式逐条执行指令。
:::

可以使用以下命令配置 CPU 的性能（在本例中，设置为 120 _MIPS_）：

```none
cpu PerformanceInMips 120
```

性能设置的默认值为 100 _MIPS_。

## 时间源和接收器

控制 _虚拟时间_ 流的对象称为 _时间源_ 。默认情况下，有一个时间 _源_  ，称为  _master time source_，与仿真相关联。目前，没有用于创建其他 _主时间源_ 的 API，但框架本身能够处理多个 _时间域_  （每个_主时间源_都是域的根）。

知道时间流向的对象称为 _时间槽_ 。每个 _sink_ 都只连接到一个 _source_（随时，尽管它可以更改 _source_），并等待有关到目前为止经过了多少 _虚拟时间_ 的信息。

有些对象同时扮演两个角色： _sink_ 和 _source_ - 它们被称为 _slave time sources_。下一节将解释具有  _slave 时间源_ 的原因。

## 同步

虚拟时间以 _quant_ 的形式流动，由 _master time sources_ 生成并授予 _sink_。_quant_ 的值以 _虚拟秒_ （或其一小部分）表示，可由用户配置。

将  _quant_ 授予 _sink_  后，_source_  将等待它们完成执行。一旦所有 slave 都报告了，就该进入 _synchronization 阶段_ 了。由于可以保证在此阶段没有节点工作，因此在此期间处理所有节点间通信是安全的。只有当 _同步阶段_ 完成时，才能向所有  _sink_ 授予新的 _quant_。

可以在 _域_ 中引入 _从时间源_ ，将量子分成更小的片段，并允许所选节点更紧密地同步。

## 时域

连接在一起的时间 _源_ 和 _时间从属_ 的配置称为 _时域_ 。 _时域_ 的所有成员都观察同一 _虚拟时间_ 的流动，并一起同步。如果有多个 _时域_ ，则它们之间的时间值没有可比性 - 换句话说，不同 _时域_ 之间没有同步。

默认情况下，仿真中有一个 _时间域_ 。 _主时间源_ 与仿真本身相关联，每台机器都提供自己的 _从时间源_ ，该 _时间源_ 驱动 CPU 成为 _接收器_ 。

## 配置和监控

_时间源_ 提供了几个可用于优化 _虚拟时间_ 流的属性：

*量子*

	:   两个 _同步阶段_ 之间的 _虚拟时间_ 量。可以保证，两个 _从站_ 感知到的 _虚拟时间_ 差永远不会高于其最近的公共 _源_ 的 _量子_  。
    
	  可以在 _同步阶段_ 之间更改  _quantum_ 的值，但在下一次授权之前不会使用新值。
    
	_从属时间源_ 可以具有与其 _主时间源_ 不同的 _量程_ 。如果 slave 的 quantum 小于 master 的 quantum，则 slave 会将 quantum 拆分成更小的块，并仅在所有 fragment 都用完时返回 master 报告。如果 slave 的 quantum 大于 master 的 quantum ，则 slave 将立即报告 （不执行任何 CPU 指令） 并累积授予的间隔，直到达到所需的 quantum 。
    
    将  _quantum_ 设置 _为零_ 是非法的，因为它根本不允许虚拟 _时间_ 过去。

_立即前进_

:   可用于强制仿真以主机系统允许的速度执行的布尔值。默认情况下（即未启用 *AdvanceImmediately* 时），每当 Renode 检测到 *虚拟时间* 的流逝速度超过_实时时间_时，它就会减慢指令的执行速度。

还有一些只读属性可用于监视_源_的当前状态：

_当前负载_

:   浮点值是模拟给定_虚拟时间间隔_所需的_实际时间_比率，计算为 _10_ 个样本的平均值。

_累积负荷_

:   与 `Load` 相同，但计算为自仿真开始以来所有样本的平均值。

_已用虚拟时间_

:   自_源_启动以来经过的 _虚拟时间_ 量。

_最近同步点_

:   最近的_同步阶段_的时间戳。

_SyncPoint 数量_

:   到目前为止_执行的同步阶段_数。

## CPU 暂停 vs. 中断

当 _time domain_ 的任何成员暂停其执行时，它将有效地阻止_虚拟时间_的流逝。因此，所有其他成员将执行到最近的_同步阶段_ ，并等待暂停的成员继续。

有时，在_域中_有一个被禁用但不阻止其他成员的成员很方便 - 例如，在多 CPU 架构中未计时的 CPU。_CPU_ 类提供了 `IsHalted` 属性，可用于实现此目标。
